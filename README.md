# Unsozoro（あんそぞろ）

## 1. 概要

### 1.1 ゲーム名

**Unsozoro（あんそぞろ）**

### 1.2 コンセプト

「そぞろ歩き」に目的を与え、ゲームとして楽しめるようにする位置情報ブラウザゲーム。

プレイヤーは散歩コースを選択し、マップを見ながら実際に街を歩く。

歩いた場所は「踏破済み」として記録され、コース内に設定されたチェックポイントを発見することでゲームが進行する。

### 1.3 MVPの目的

MVPでは以下の体験を成立させる。

> **コースを選ぶ → 地図を見ながら歩く → 歩いた場所が開拓される → チェックポイントを発見する**

### 1.4 設定

公開URL

https://usz.reload.co.jp

---

# 2. MVPの機能範囲

MVPでは以下の機能を実装する。

* コース一覧取得
* コース選択
* コース情報取得
* 全画面マップ表示
* 現在地表示
* チェックポイント表示
* GPSによる移動検知
* 踏破エリアの記録
* 未踏エリアのグレーアウト
* チェックポイント発見判定
* 発見済みチェックポイントの保存
* プレイ状態のブラウザ保存
* コースクリア判定

以下はMVPでは実装しない。

* ユーザーアカウント
* サーバーへのプレイデータ保存
* SNS
* ランキング
* 実績
* 複数ユーザー間の比較
* 課金
* 通知
* オフライン地図
* 複雑なゲームルール

# 5. コース選択

メニューボタンからコース一覧を表示する。

## 5.1 コース一覧API

```http
GET https://sozoroto.reload.co.jp/api/courses/list.json
```

APIから取得したコースを一覧表示する。

### コース一覧表示項目

MVPではAPIから取得できる情報のうち、最低限以下を表示する。

* コース名
* コース説明
* コースID

APIに存在しない項目は表示しない。

---

# 6. コース詳細取得

コース選択時にコース詳細を取得する。

```http
GET https://sozoroto.reload.co.jp/api/courses/{id}.json
```

取得したコース情報をゲーム開始時に利用する。

### 必須データ

コースには最低限以下の情報が必要。

* コースID
* コース名
* コース範囲
* チェックポイント

チェックポイントには以下の情報が必要。

* チェックポイントID
* 名称
* 緯度
* 経度

その他のフィールドはAPI仕様に合わせる。

# 7. マップ

## 7.1 マップ表示

コースの範囲が画面内に収まるように初期表示する。

プレイヤーの現在地が取得できた場合は、現在地を中心に表示する。

## 7.2 地図タイル

コース範囲内の地図タイルを表示する。

使用する地図ライブラリは実装時に決定する。

候補：

* MapLibre GL JS
* Leaflet

---

# 8. 現在地

ブラウザのGeolocation APIを使用する。

```javascript
navigator.geolocation.watchPosition(...)
```

位置情報を継続的に取得する。

### 取得する情報

```text
latitude
longitude
accuracy
timestamp
```

### 現在地表示

マップ上に現在地マーカーを表示する。

```text
       🚶
     現在地
```

GPS精度が低い場合は、取得した`accuracy`を考慮して位置を利用する。

---

# 9. 移動ログ

プレイヤーの移動位置を取得し、ブラウザに保存する。

1回の位置情報取得ごとに以下を記録する。

```json
{
  "latitude": 35.000000,
  "longitude": 139.000000,
  "timestamp": 1750000000000,
  "accuracy": 10
}
```

ただし、GPSの細かな揺れを大量に保存しないよう、一定距離以上移動した場合のみ記録する。

---

# 10. 踏破システム

## 10.1 基本仕様

プレイヤーが歩いた場所を踏破済みとして表示する。

マップを一定サイズのグリッドに分割し、訪問したグリッドを記録する。

```text
┌───┬───┬───┬───┐
│未踏│未踏│未踏│未踏│
├───┼───┼───┼───┤
│未踏│踏破│踏破│未踏│
├───┼───┼───┼───┤
│未踏│踏破│踏破│未踏│
├───┼───┼───┼───┤
│未踏│未踏│未踏│未踏│
└───┴───┴───┴───┘
```

## 10.2 表示

### 未踏

グレーアウトする。

### 踏破済み

通常の地図を表示する。

これにより、

> 「自分が歩いた場所だけが見える」

というゲーム性を作る。

---

# 11. 踏破判定

GPSで取得した現在地を踏破グリッドに変換する。

```text
GPS座標
   ↓
コース範囲内か確認
   ↓
グリッド座標へ変換
   ↓
踏破済みに変更
   ↓
マップ更新
```

コース範囲外の位置は踏破対象にしない。

---

# 12. 踏破率

コース内のグリッド数を基準に踏破率を計算する。

```text
踏破率 =
踏破済みグリッド数
÷
コース内グリッド数
× 100
```

マップ上に表示する。

例：

```text
踏破率 42%
```

---

# 13. チェックポイント

コースに設定されたチェックポイントをマップ上に表示する。

```text
○ 未発見
● 発見済み
```

MVPではチェックポイントの位置を常に表示する。

---

# 14. チェックポイント発見

現在地とチェックポイントの距離を計算する。

```text
現在地
   ↓
チェックポイントとの距離を計算
   ↓
設定距離以内？
   ├─ NO → 未発見
   └─ YES → 発見
```

### 発見判定距離

MVPでは仮値として**50m以内**を使用する。

実際のGPS精度やゲームプレイを確認して調整する。

---

# 15. チェックポイント発見時

チェックポイントを発見済みに変更する。

例：

```text
┌────────────────────┐
│                    │
│  チェックポイント発見！ │
│                    │
│      ○○神社         │
│                    │
│       [OK]         │
└────────────────────┘
```

発見済み情報を保存する。

---

# 16. コースクリア

すべてのチェックポイントを発見するとコースクリアとする。

```text
チェックポイント
5 / 5

↓

コースクリア
```

踏破率はクリア条件には含めない。

つまり、

> **すべてのチェックポイントを発見すればクリア**

とする。

踏破率は追加の達成度として表示する。

---

# 19. 再開

ブラウザを閉じてもプレイ状態を保持する。

ゲーム再起動時、

```text
保存済みプレイデータあり
        ↓
プレイ中のコースを復元
        ↓
踏破エリアを復元
        ↓
チェックポイント状態を復元
        ↓
ゲーム再開
```

---

# 20. コースの切り替え

別のコースを選択した場合、新しいコースのゲーム状態を読み込む。

各コースの進行状況は独立して保存する。

```text
course-A
  ├─ 踏破データ
  └─ CP状態

course-B
  ├─ 踏破データ
  └─ CP状態
```

# 22. エラー処理

## 22.1 位置情報が利用できない

```text
位置情報を取得できません。

ブラウザの位置情報設定を
確認してください。
```

## 22.2 コース一覧取得失敗

```text
コース一覧を取得できませんでした。

通信状態を確認してください。
```

## 22.3 コース詳細取得失敗

```text
コース情報を取得できませんでした。
```

## 22.4 GPS精度が低い

GPSの`accuracy`が一定値を超える場合、その位置を踏破判定に使用しない。

閾値は実装時に調整する。

# 26. MVPの体験

MVPでは機能を増やすことより、以下の体験を成立させることを優先する。

```text
        コースを選ぶ
             ↓
       ┌───────────┐
       │    MAP    │
       │           │
       │  ○ CP     │
       │           │
       │     🚶    │
       │           │
       └───────────┘
             ↓
           歩く
             ↓
      歩いた場所が開く
             ↓
       ○ CPを発見
             ↓
       次のCPを探す
             ↓
       すべて発見
             ↓
        COURSE CLEAR
```

チェックポイントは「歩く理由」を作るためのゲーム要素として扱い、踏破エリアの拡大をUnsozoroの主要なゲーム体験とする。
